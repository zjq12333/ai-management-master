# AI管理大师

AI管理大师是一个面向本地 Codex Desktop 的启动前管理器和聊天记录恢复工具。

它现在主要做三件事：

- 在启动 Codex 之前，先选择本次要使用的通道；
- 自动检查并对齐聊天记录所属的 provider 桶；
- 恢复左侧历史和工作区，然后直接启动 Codex Desktop。

## 适合处理的问题

- 切换 API 供应商后，历史聊天突然不见了；
- 切回官方账号后才能看见聊天，非官方通道看不见；
- 想在启动 Codex 之前，先把聊天记录和通道关系整理好；
- 不想手动改 `config.toml`、手动 sync、再自己启动 Codex。

## 最推荐的用法

打开图形界面：

```text
Run-CodexMaintenanceGUI.vbs
```

推荐流程：

1. 打开 AI管理大师。
2. 确认顶部显示“有效 Codex 数据目录”。
3. 在“启动前配置”里选择本次使用方式：
   - `官方账号`
   - `API 供应商`
4. 如果是 `API 供应商`，填写：
   - `provider 键`
   - `显示名称`
   - `base_url`
   - `wire_api`
   - `env_key`
5. 点击 `配置并启动 Codex`。
6. 工具会自动：
   - 写入本次要用的 provider 配置
   - 检查当前聊天桶是否匹配
   - 自动修复隐藏聊天识别
   - 恢复聊天记录和工作区
   - 启动 Codex Desktop

如果你只是想先看看当前能恢复多少聊天，也可以先点：

```text
搜索聊天记录
```

## 官方账号模式

选择 `官方账号` 时，工具会先把当前目标通道切回官方通道，再对齐聊天记录，然后启动 Codex。

真正的账号登录动作仍然是在 Codex 自己的界面里完成，但聊天桶和恢复准备会在启动前先处理好。

## API 供应商模式

选择 `API 供应商` 时，工具会先把你填写的 provider 信息写进配置，再按这个通道对齐聊天记录，最后启动 Codex。

这一步的目标是避免“先登录一次失败，退出来再修”的情况。

## 高级设置说明

高级设置默认不用动，只有你明确知道自己要恢复什么时再打开。

- `包含归档`
  会把已归档聊天也列入搜索和恢复结果。

- `允许已删除工作区`
  会显示原工作目录已经不存在的聊天。

- `允许空工作区`
  会显示目录还在但已经空掉的聊天。

- `允许缺失 session`
  会显示找不到会话文件的记录，这类记录可能无法完整打开。

- `取消所选归档标记`
  正式恢复时会把选中的归档聊天改成未归档。

- `强制修复隐藏聊天识别`
  默认会在检测到不匹配时自动尝试。勾选后会在恢复时强制执行一次。

- `允许安装 threadripper`
  会通过 npm 安装辅助工具，需要联网。

## 安全默认行为

默认只恢复“真实、可见、仍然有效”的聊天。

默认包含：

- 有用户消息的会话；
- 未归档的会话；
- 仍然有对应会话文件的会话；
- 工作目录仍然存在的会话；
- 工作目录不是空文件夹的会话。

默认跳过：

- 已归档会话；
- 已删除工作区对应的会话；
- 空工作区对应的会话；
- 没有用户消息的空线程；
- 找不到会话文件的线程。

正式运行前会自动备份关键状态文件，不会直接删除聊天内容。

- 直接启动 Codex Desktop
